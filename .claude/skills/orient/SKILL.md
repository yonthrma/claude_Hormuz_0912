# orient — 코드베이스 파악

대상: $ARGUMENTS (비었으면 현재 저장소 전체)

## 원칙

**전부 읽지 않는다.** 목표는 완벽한 이해가 아니라 **다음에 어디를 열어야 할지 아는 것**이다.
20분 안에 끝나야 한다. 안 끝나면 범위를 좁힌다.

그리고 **확인한 것과 추측한 것을 반드시 구분한다.** 이 스킬의 결과물은
나중에 남이 믿고 읽는 문서다. 추측을 사실처럼 적으면 안 하느니만 못하다.

| 표시 | 뜻 |
| --- | --- |
| ✅ | 코드를 직접 열어서 확인했다 |
| 🔍 | 파일명·구조에서 추론했다. 확인 필요 |
| ❓ | 모르겠다. 사람에게 물어야 한다 |

---

## 절차

### 1. 지도 (2분)

- 파일 트리를 훑는다. 깊이 2~3단계까지만.
- 규모를 잰다: 파일 수, 총 줄 수, 가장 큰 파일 5개
- 언어·빌드 도구를 확정한다 (`package.json`, `pyproject.toml`, `go.mod`, `Cargo.toml`, `requirements.txt`)
- README·CLAUDE.md 가 있으면 읽는다. **단, 문서는 낡았을 수 있다.** 문서에서 얻은 사실은 🔍 로 표시하고 코드로 확인될 때 ✅ 로 올린다.

### 2. 진입점 (3분)

프로그램이 **어디서 시작하는가**를 찾는다.

| 종류 | 찾을 것 |
| --- | --- |
| CLI | `main`, `__main__`, `bin/`, `scripts` 항목 |
| 웹 서버 | 라우터 등록, `app.listen`, `urls.py`, `routes/` |
| 라이브러리 | 공개 API — `index.*`, `__init__.py`, `lib.rs` |
| 배치·스크립트 | cron 설정, GitHub Actions, `Makefile` |

진입점이 여러 개면 전부 나열하고, **가장 자주 쓰이는 것 하나**를 골라 3단계로 간다.

### 3. 흐름 한 줄 추적 (7분)

대표 시나리오 **하나만** 골라 처음부터 끝까지 따라간다.
(예: "사용자가 로그인한다", "CSV를 넣으면 리포트가 나온다")

```
입력 진입점 → 검증 → 핵심 로직 → 저장/출력 → 응답
   파일:줄     파일:줄    파일:줄      파일:줄     파일:줄
```

각 단계에 **파일명과 줄 번호**를 붙인다. 이게 이 스킬 결과물의 핵심 가치다.
중간에 이해 안 되는 점프가 있으면 ❓ 로 남기고 계속 간다. 거기서 멈추지 않는다.

### 4. 경계 (3분)

이 코드가 **바깥과 닿는 지점**을 찾는다. 사고는 대부분 여기서 난다.

- 외부 API 호출
- 데이터베이스 / 파일 시스템
- 환경 변수, 설정 파일, 비밀 값
- 다른 팀·다른 저장소에 대한 의존

### 5. 위험 지점 (3분)

- 테스트가 **없는** 핵심 로직
- `TODO`, `FIXME`, `HACK`, `임시`
- 500줄 넘는 파일 / 100줄 넘는 함수
- 마지막 수정이 아주 오래된 파일 (`git log -1 --format=%ar -- <파일>`)
- 주석과 코드가 서로 다른 말을 하는 곳

### 6. 정리 (2분)

산출물을 쓰고, **사용자에게 ❓ 목록을 낸다.** 한 번에 하나씩 묻는다.

## 하지 말 것

- 파일을 전부 읽기 — 시간만 쓰고 지도가 안 나온다
- 추측을 ✅ 로 적기 — 이게 이 스킬을 망치는 유일한 방법이다
- 코드 고치기 — 이 스킬은 **읽기만** 한다. 고칠 게 보이면 목록에 적고 사용자에게 알린다
- 이해 안 되는 곳에서 멈추기 — ❓ 남기고 끝까지 간다
- README 내용을 확인 없이 사실로 옮기기 — 문서는 낡는다
