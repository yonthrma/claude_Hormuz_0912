# route — 알아서 판단해서 진행하기

요청: $ARGUMENTS

## 이 스킬이 하는 일

사용자가 "이거 해줘"라고만 해도, **어떤 스킬을 어떤 순서로 쓸지 판단해서 그대로 진행한다.**

판단은 `dispatcher` 에이전트에게 맡기고, 실행은 본 세션이 한다. 역할이 나뉜 이유:

| | dispatcher (서브에이전트) | 본 세션 (나) |
| --- | --- | --- |
| 하는 일 | 저장소 조사 + 계획 수립 | 계획 실행 |
| 사용자와 대화 | ❌ 불가 | ⭕ 가능 |
| 파일 수정 | ❌ 안 함 | ⭕ 함 |

`interview`, `set-goal`, `grill` 은 **사용자에게 묻고 답을 기다리는** 스킬이라
서브에이전트 안에서는 작동하지 않는다. 그래서 판단만 떼어 맡긴다.

---

## 절차

### 1. 요청이 비었으면 묻는다

`$ARGUMENTS` 가 비었으면 한 줄만 묻는다:
> "무엇을 해드릴까요? 다듬지 않은 문장이어도 됩니다."

### 2. XS 는 에이전트를 부르지 않는다

아래에 해당하면 **에이전트 호출 없이 바로 처리한다.** 판단 자체가 낭비다.

- 오타 수정, 한 줄 변경, 파일 하나 읽기
- 질문에 답하기, 명령어 알려주기
- 사용자가 이미 스킬을 지목함 (`/tdd 해줘`) → 그 스킬로 바로 간다

이때는 이렇게만 말한다: "작은 일이라 스킬 없이 바로 처리하겠습니다."

### 3. dispatcher 를 호출한다

Agent 도구로 `subagent_type: dispatcher` 를 호출하고, 프롬프트에 담는다:

- 사용자의 요청 원문 (요약하지 말고 그대로)
- 이번 대화에서 이미 나온 관련 맥락 (있으면)

### 4. 계획을 사용자에게 보여준다

돌아온 계획을 **그대로** 보여준다. 내가 임의로 단계를 더하거나 빼지 않는다.
동의하지 않는 부분이 있으면 계획을 고치지 말고, 계획 아래에 내 의견을 따로 적는다.

그리고 확인받는다:
> "이 순서로 진행할까요? 빼고 싶은 단계가 있으면 말씀해 주세요."

**승인 없이 실행하지 않는다.** 단, 계획이 "스킬 없이 바로 처리"면 확인 없이 진행해도 된다.

### 5. `물어볼 것` 을 먼저 해소한다

에이전트가 남긴 질문을 **한 번에 하나씩** 묻는다. 전부 나열하지 않는다.
질문이 4개를 넘으면 그건 `interview` 를 해야 한다는 신호다. 계획을 그렇게 바꾸자고 제안한다.

### 6. 계획대로 실행한다

- 스킬을 **하나씩** 실행한다. 하나 끝나면 결과를 요약하고 다음으로 넘어간다
- 단계 사이에 멈추고 확인받는다. 전부 한 번에 쏟아내지 않는다
- 실행 중 계획이 틀렸다는 게 드러나면 **멈추고 사용자에게 알린다.** 혼자 경로를 바꾸지 않는다

### 7. 끝나면 정리한다

- 무엇을 했는지, 어떤 문서가 생겼는지 목록으로
- 다음에 할 만한 것 한 줄
- 작업이 길었으면 `/handoff` 를 권한다

---

## 실행 중 경로가 바뀌는 경우

계획대로 안 되는 건 흔하다. 아래는 **정상적인 경로 변경**이니 사용자에게 알리고 진행한다.

| 발견 | 바꾸는 방향 |
| --- | --- |
| 명세를 쓰다 보니 목표가 흔들린다 | `set-goal` 로 되돌아간다 |
| 인터뷰 답이 계속 "모르겠다" | 범위를 줄이거나, 작은 시험판을 먼저 만든다 |
| 테스트를 쓰기가 유난히 어렵다 | 설계 신호다. `spec` 이나 `adr` 로 잠깐 나간다 |
| 코드가 예상과 다르게 생겼다 | `orient` 를 먼저 넣는다 |
| 되돌리기 비싼 선택을 하게 됐다 | `adr` 를 끼워 넣는다 |

---

## 하지 말 것

- 계획 없이 큰 작업을 시작하기 (M/L 인데 dispatcher 를 건너뛰기)
- **작은 일에 에이전트 부르기** — XS/S 는 바로 처리한다. 판단 비용이 작업보다 커진다
- 에이전트가 낸 계획을 조용히 고치기 — 이견은 따로 적는다
- 승인 없이 여러 단계를 연달아 실행하기
- 사용자가 지목한 스킬을 무시하고 다른 걸 쓰기

## 예시

**"출석 체크하는 걸 만들고 싶어"**
→ L 판정 → `dev-loop` (목표부터 흐리므로 처음부터)

**"이 CSV 파싱 함수에 빈 줄 처리 좀 추가해줘"**
→ S 판정 → `tdd` 단독 (빈 줄 케이스 테스트 먼저)

**"README 오타 고쳐줘"**
→ XS 판정 → 스킬 없이 바로

**"이 레포 처음 보는데 로그인이 어떻게 도는 거야"**
→ `orient` 단독 (대표 흐름을 로그인으로 잡고 추적)

**"DB를 sqlite 로 갈까 postgres 로 갈까"**
→ `interview grill` → `adr` (결정과 되돌리는 법을 남긴다)
