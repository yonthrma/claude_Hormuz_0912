# 디자인.md — 공업화학 시험 대비 사이트의 모양 규칙

- 작성일: 2026-09-12
- 쓰는 곳: `exam-site/app/templates/` 전부
- 이후 모든 요청에 이 줄을 붙인다: **"디자인.md에 적힌 규칙을 그대로 지켜서 만들어 줘. 새로운 스타일을 만들지 마."**

## 이 화면이 쓰이는 상황

시험 전날 밤, 불을 끈 방이나 지하철에서 **폰 한 손으로 오래** 본다.
그래서 모든 판단의 기준은 "예쁜가"가 아니라 **"어두운 데서 30분 봐도 눈이 안 아픈가"**다.
둘이 충돌하면 눈이 이긴다.

## 성격

종이 공책 느낌. 크림색 바탕, 두꺼운 테두리, 또렷한 기호.
장식은 **테두리 · 점 무늬 · 레이스**로만 낸다. 그라데이션·그림자·번쩍이는 색으로 내지 않는다.

### 레이스

- **CSS 로만 그린다.** 그림 파일을 쓰지 않는다 (인터넷을 타면 안 되므로).
  `mask-image: radial-gradient(...)` 로 동그란 물결(스캘럽)을 만들고, 그 아래 점을 한 줄 찍는다.
- 두는 곳은 **두 군데까지**: 상단바 아래, 카드 머리띠 아래. 더 붙이면 글이 안 읽힌다.
- 레이스는 **장식일 뿐 뜻이 없다.** `aria-hidden="true"` 를 붙여 읽어 주지 않게 한다.
- 굵기는 11px 이하. 이보다 두꺼우면 본문 자리를 먹는다.

---

## 1. 바탕색과 글자색

두 벌을 만든다. **밤(어두운) 화면이 기본에 가깝다.** 폰의 시스템 설정을 따르되,
화면 오른쪽 위 버튼으로 직접 바꿀 수 있고 그 선택을 기억한다.

### 낮 (종이)

| 쓰임 | 색 | 비고 |
| --- | --- | --- |
| 바탕 | `#FDF4E7` | 흰색을 쓰지 않는다. 크림색이 눈부심이 덜하다 |
| 바탕 점무늬 | `#E9D3B4` | 16px 간격, 1.4px 점 |
| 카드 | `#FFFFFF` | 글이 얹히는 면만 흰색 |
| 본문 글자 | `#3E2A1C` | 바탕 대비 약 11:1 |
| 보조 글자 | `#6E533A` | 출처·쪽수 등. 이보다 흐린 색을 쓰지 않는다 |
| 굵은 테두리 | `#4E3524` | |
| 띠 위 글자 | `#FDF4E7` | 갈색 띠 위에 얹는 글자색 |
| 연한 테두리 | `#D9C4A9` | |
| 포인트 | `#7A2A46` (글자) / `#FFE3EE` (바탕) | 주요 버튼과 링크에만 |

### 밤 (기본)

| 쓰임 | 색 | 비고 |
| --- | --- | --- |
| 바탕 | `#1A1512` | 순검정을 쓰지 않는다. 잔상이 덜하다 |
| 바탕 점무늬 | `#2A211B` | |
| 카드 | `#241C17` | |
| 본문 글자 | `#F0E4D4` | 순백을 쓰지 않는다. 대비 약 12:1 |
| 보조 글자 | `#B79C7E` | |
| 굵은 테두리 | `#4E3524` | 낮과 같은 갈색을 쓴다. 밤에 금색은 너무 튄다 |
| 띠 위 글자 | `#F0E4D4` | 갈색 띠(상단바·카드 머리) 위에 얹는 글자색 |
| 연한 테두리 | `#4A3B2E` | |
| 포인트 | `#FFC0D8` (글자) / `#4A2233` (바탕) | |

**규칙:** 본문 글자와 바탕의 대비는 어느 화면에서든 **7:1 이상**이어야 한다.
보조 글자도 **4.5:1 아래로 내려가지 않는다.** 흐리게 해서 위계를 만들지 말고 크기와 굵기로 만든다.

## 2. 글자 크기

| 쓰임 | 크기 | 굵기 |
| --- | --- | --- |
| 화면 제목 | 20px | 800 |
| 단원 이름 · 카드 제목 | 17px | 700 |
| 문제 지문 | 17px | 700 · 줄간격 1.55 |
| 선택지 | 15px | 600 |
| 해설 본문 | 15px | 400 · 줄간격 1.7 |
| 출처 · 쪽수 · 보조 | 13px | 600 |

**13px보다 작은 글자를 쓰지 않는다.** 공간이 모자라면 글자를 줄이지 말고 내용을 줄인다.
**굵기 400 아래를 쓰지 않는다.** 얇은 글씨는 어두운 화면에서 흐려 보인다.

글꼴은 **기기에 있는 것만 쓴다. 인터넷에서 불러오지 않는다.**
지하철에서 안 터져도 똑같이 보여야 한다.
`Galmuri11` 같은 픽셀 글꼴을 목록 맨 앞에 두되, 없으면 시스템 글꼴로 조용히 넘어간다.
제목·번호·버튼에만 그렇게 하고, **해설처럼 긴 글에는 장식 글꼴을 쓰지 않는다.**

## 3. 문제 한 개가 차지하는 영역

문제 하나 = 카드 하나. 위에서 아래로 이 순서를 지킨다.

```
┌─ 번호띠 ────────────────────┐   ← 굵은 테두리 색으로 채운 띠, 13px
│ 3 / 14          1.2 단원     │
├─────────────────────────────┤
│ 문제 지문 (17px)             │
│                              │
│ [ ① 선택지 ]                 │   ← 각각 최소 높이 48px
│ [ ② 선택지 ]                 │
│ [ ③ 선택지 ]                 │
│ [ ④ 선택지 ]                 │
├─ 해설 (답한 뒤에만 나타남) ──┤   ← 점선 테두리
│ 판정 한 줄 → 해설 → 근거 원문 │
│ → 출처 링크                   │
└─────────────────────────────┘
```

- 테두리 3px, 모서리 10px.
- **바깥 이중선(outline)은 지금 풀고 있는 문제 카드에만** 쓴다.
  단원 목록처럼 여러 개가 깔리는 곳에 쓰면 시끄럽다.
- 카드 사이 간격 18px. 카드 안쪽 여백 16px.
- 해설은 **점선** 테두리로 본문과 구분한다. 색만으로 구분하지 않는다.
- 근거 원문 인용은 해설 안에 따옴표로 넣고, 바로 아래 출처를 링크로 둔다.

## 4. 정답일 때와 틀렸을 때

**색만으로 구분하지 않는다. 기호를 반드시 함께 쓴다.**
화면 밝기를 낮췄거나 색이 잘 구분되지 않아도 알아볼 수 있어야 한다.

| 상태 | 기호 | 낮 | 밤 |
| --- | --- | --- | --- |
| 정답 | `✔` | 글자 `#00614A` / 바탕 `#D9F9F0` / 테두리 `#00B88E` | 글자 `#7BE0C0` / 바탕 `#123227` / 테두리 `#2E8F72` |
| 내가 고른 오답 | `✘` | 글자 `#8A2B2B` / 바탕 `#F7E0E0` / 테두리 `#C25A5A` | 글자 `#FF9C93` / 바탕 `#3A1C19` / 테두리 `#A85C54` |
| 고르지 않은 것 | 번호 그대로 | 연한 테두리, 바탕 그대로 | 같음 |

- 답한 뒤 **정답은 항상 표시한다.** 맞혔든 틀렸든 정답 자리가 어디인지 보여준다.
- 판정 문구는 "정답입니다" / "틀렸습니다" 로 짧게. 칭찬이나 응원 문구를 붙이지 않는다.
- 저장이 실패하면 **실패했다고 화면에 적는다.** 성공한 것처럼 보이게 두지 않는다.

## 5. 버튼

- 높이 **최소 48px**. 엄지로 누르는 크기다.
- 모서리 8px, 테두리 2px. 글자 굵기 800.
- **주요 버튼은 화면에 하나만.** 포인트 색 바탕에 포인트 글자색.
  나머지는 연한 테두리에 바탕 그대로(보조 버튼).
- 위치: 화면 흐름의 **아래쪽**, 손가락이 닿는 곳.
  **동작 버튼은 화면에 고정해 띄우지 않는다.** 글을 가리기 때문이다.
  예외는 아래의 이동 막대 하나뿐이다.
- 버튼은 `<button>`이나 `<a>`로 만든다. 눌리는 것처럼 보이는 `<div>`를 쓰지 않는다.
- 두 개를 나란히 둘 때는 **왼쪽이 보조, 오른쪽이 주요**.

## 5-2. 아래 이동 막대 (작업줄)

화면 맨 아래에 **늘 붙어 있는 이동 막대**를 둔다. 폰에서 엄지가 닿는 자리다.
숨김 메뉴(햄버거)를 쓰지 않는다. 눌러야 보이는 메뉴는 못 찾는다.

- 칸은 **4개까지.** 더 필요하면 그건 메뉴가 아니라 화면 안에 둘 내용이다.
- 각 칸은 **글자로 이름을 적는다.** 그림만 있는 칸을 두지 않는다.
- 지금 보고 있는 칸은 포인트 색으로 칠하고, 나머지는 보조 글자색.
- 높이 최소 **56px**. 본문이 가리지 않게 `body` 아래 여백을 그만큼 준다.
- 알림 숫자(오답 개수 등)는 이름 옆에 **숫자 그대로** 적는다. 빨간 점만 찍지 않는다.

## 5-1. 말투

화면에 나오는 모든 글은 **부드러운 존댓말**로 쓴다. 명령형("~해라", "~하지 마")을 쓰지 않는다.

| 이렇게 | 이러지 말고 |
| --- | --- |
| 날짜를 누르면 계획을 적을 수 있어요 ^~^ | 날짜를 눌러 계획을 적어라 |
| 아직 계획이 없어요. 천천히 채워도 괜찮아요 | 이번 주 계획이 없다 |
| 오늘 목표 다 채웠어요! ^~^ | 오늘 목표를 채웠다 |
| 3문제만 더 풀면 돼요 | 3문제 남았다 |

- 웃는 표정 `^~^` `^^` 는 **한 화면에 한두 번까지만**. 줄마다 붙이면 지저분해진다.
- 그림 이모지(🎉 같은 것)는 쓰지 않는다. 글자 표정만 쓴다.
- **틀렸을 때 놀리거나 재촉하지 않는다.** "아쉬워요", "다시 한번 볼까요?" 정도로 담담하게.
- **실패는 부드럽게 말하되 사실은 흐리지 않는다.**
  "저장이 안 됐어요. 이 기록은 남지 않아요" — 성공한 것처럼 보이게 두지 않는다.
- 숫자와 판정(정답/오답, D-day, 남은 문제 수)은 말투와 상관없이 **정확하게** 적는다.

## 6. 쓰지 말 것

- **애니메이션과 전환 효과.** 나타나고 사라지는 움직임을 넣지 않는다.
  틀린 문제를 다시 볼 때 기다리게 만드는 것이 가장 나쁘다.
- **그림자 남발.** 카드에 그림자를 쓰지 않는다. 구분은 테두리로 한다.
- **얇은 글씨(400 미만), 13px 미만 글자, 흐린 회색 본문.**
- **인터넷에서 불러오는 글꼴·아이콘·이미지.**
- **색만으로 전달하는 정보.** 정답·오답·경고 전부 기호나 글자를 함께 둔다.
- **가로 스크롤.** 폭 375px에서 가로로 밀리면 안 된다. 표는 스크롤 상자 안에 가둔다.
- **명령형 말투.** 5-1 참고.
- **그림 이모지와 과한 축하.** 글자 표정 `^~^` 정도까지만.

## 이 규칙을 지켰는지 확인하는 법

```
python build/04_check_mobile.py   # 가로 넘침 원인 0건이어야 한다
python build/05_verify.py         # 완료 기준 전부 통과여야 한다
```

눈으로도 본다: **불을 끄고 폰으로 열어 30초 본다.** 눈이 부시면 규칙이 아니라 화면이 틀린 것이다.
